## 10. 详细数据结构定义

### 10.1 核心数据模型

#### 10.1.1 上下文实体（ContextEntity）
```typescript
// 这是TypeScript类型定义，用于说明数据结构，并非实际代码
interface ContextEntity {
  id: string; // 唯一标识符，格式为"文件路径:起始行:起始列"
  type: 'function' | 'class' | 'interface' | 'variable' | 'import' | 'comment';
  filePath: string; // 绝对路径
  name: string; // 函数名、类名等
  content: string; // 实际的代码片段
  range: { // 在文件中的位置
    start: { line: number; character: number };
    end: { line: number; character: number };
  };
  language: string; // 'typescript', 'python', 'java'等
  metadata: {
    complexity?: number; // 圈复杂度或其他复杂度指标
    lastModified?: string; // ISO时间戳
    author?: string; // 最后修改者
    gitCommit?: string; // 关联的提交哈希
  };
}
```

#### 10.1.2 关系边（RelationshipEdge）
```typescript
interface RelationshipEdge {
  sourceId: string; // 源实体ID
  targetId: string; // 目标实体ID
  type: 'calls' | 'inherits' | 'implements' | 'references' | 'similar';
  strength: number; // 关系强度，0-1之间
  evidence: string[]; // 证明此关系的代码片段或分析依据
  bidirectional: boolean; // 是否双向关系
}
```

#### 10.1.3 上下文包（ContextBundle）
```typescript
interface ContextBundle {
  id: string; // 包ID，基于时间戳和焦点实体生成
  focusEntity: ContextEntity; // 开发者当前聚焦的实体
  contextEntities: Array<{
    entity: ContextEntity;
    relevanceScore: number; // 相关性评分，0-100
    inclusionReason: string; // 包含原因的可读描述
    layer: 'core' | 'important' | 'reference'; // 所属层级
    tokenCount: number; // 占用的token数量
  }>;
  summary: {
    totalTokens: number;
    entitiesByLayer: Record<string, number>;
    primaryRelations: string[]; // 主要关系类型
    estimatedAIQuality: number; // 预测的AI生成质量评分
  };
  timestamp: string; // 生成时间
}
```

## 11. 事件系统设计

### 11.1 内部事件总线

#### 11.1.1 事件类型枚举
```
ANALYSIS_STARTED       - 开始分析项目
ENTITY_DISCOVERED      - 发现新代码实体
RELATIONSHIP_FOUND     - 发现实体间关系
CONTEXT_REQUESTED      - 开发者请求上下文
CONTEXT_GENERATED      - 上下文包生成完成
CACHE_HIT             - 缓存命中
CACHE_MISS            - 缓存未命中
AI_RESPONSE_RECEIVED  - 收到AI响应
USER_FEEDBACK         - 用户反馈（正/负）
ERROR_OCCURRED        - 错误发生
PERFORMANCE_METRIC    - 性能指标记录
```

#### 11.1.2 事件监听器配置
每个模块可以注册感兴趣的事件，例如：
- **UI模块**：监听`CONTEXT_GENERATED`以更新预览面板
- **缓存模块**：监听`ENTITY_DISCOVERED`以更新缓存
- **分析模块**：监听`CONTEXT_REQUESTED`以触发分析
- **监控模块**：监听所有事件以收集遥测数据

### 11.2 外部事件集成

#### 11.2.1 文件系统事件
- **文件保存**：触发增量分析，更新相关实体
- **文件重命名/删除**：更新实体索引和关系
- **目录变化**：检测新添加的源文件

#### 11.2.2 Git/版本控制事件
- **提交完成**：更新`lastModified`元数据
- **分支切换**：可选地重新分析或调整缓存策略
- **合并冲突**：标记可能需要特别关注的区域

#### 11.2.3 IDE生命周期事件
- **项目打开**：启动后台分析，加载缓存
- **项目关闭**：保存状态，清理临时资源
- **窗口焦点变化**：调整资源使用策略

## 12. 错误处理与恢复策略

### 12.1 错误分类与处理

#### 12.1.1 可恢复错误
| 错误类型 | 可能原因 | 处理策略 | 用户反馈 |
|---------|---------|---------|---------|
| 分析超时 | 大型文件或复杂关系 | 降级为部分分析，记录指标 | 状态栏提示"部分分析完成" |
| 解析失败 | 语法错误或不受支持的语言特性 | 跳过问题区域，使用文本回退 | 轻微警告，继续运行 |
| 缓存损坏 | 磁盘错误或版本不匹配 | 清除并重建缓存 | "正在重新分析项目" |
| 网络问题 | AI服务不可达 | 使用本地回退或缓存结果 | "使用缓存数据，部分功能受限" |

#### 12.1.2 不可恢复错误
| 错误类型 | 可能原因 | 处理策略 | 用户反馈 |
|---------|---------|---------|---------|
| 内存不足 | 项目过大或内存泄漏 | 优雅停止，释放资源 | "内存不足，请重启IDE" |
| 配置损坏 | 用户配置文件错误 | 恢复默认配置 | "配置已重置为默认值" |
| 插件冲突 | 与其他扩展不兼容 | 禁用冲突功能 | "检测到冲突，已调整功能" |

### 12.2 降级策略矩阵

根据系统状态提供不同质量等级的服务：

| 系统状态 | 分析深度 | 缓存使用 | AI集成 | 用户界面 |
|---------|---------|---------|--------|---------|
| **理想状态** | 完整深度分析 | 读写均使用 | 全部AI服务 | 完整功能 |
| **中等负载** | 跳过语义分析 | 优先读取 | 主要AI服务 | 简化预览 |
| **高负载** | 仅直接依赖分析 | 只读缓存 | 仅本地模型 | 最小界面 |
| **离线状态** | 无分析 | 只读缓存 | 无AI集成 | 基本界面 |

## 13. 性能优化策略

### 13.1 分析阶段优化

#### 13.1.1 延迟加载策略
1. **按需分析**：仅分析当前打开或近期编辑的文件
2. **分块处理**：大文件分割为逻辑块并行分析
3. **优先级队列**：
   - **高优先级**：当前编辑器中的文件
   - **中优先级**：导入/引用的文件
   - **低优先级**：项目中的其他文件

#### 13.1.2 增量分析机制
- **变更传播算法**：当文件修改时，仅重新分析受影响的相关实体
- **脏标记系统**：跟踪哪些分析结果已过时需要更新
- **批处理窗口**：短时间内的多次更改合并为一次分析

### 13.2 缓存优化策略

#### 13.2.1 智能预缓存
基于开发者行为模式预测可能需要的分析结果：
- **工作时段预热**：在开发者活跃时间预加载常用模块
- **项目模式学习**：记录哪些模块经常一起被编辑
- **用户习惯适应**：针对特定开发者的工作习惯优化

#### 13.2.2 缓存淘汰策略
- **LRU（最近最少使用）**：适用于实体缓存
- **LFU（最不经常使用）**：适用于关系缓存
- **基于时间的失效**：适用于元数据和统计信息
- **基于大小的限制**：防止缓存无限增长

- **颜色编码**：

## 15. 安全性设计

### 15.1 数据隐私保护

#### 15.1.1 敏感代码处理
- **本地优先原则**：所有代码分析在本地完成
- **选择性发送**：用户控制哪些上下文发送给AI服务
- **匿名化选项**：移除变量名、字符串字面量等敏感信息
- **企业模式**：完全不发送代码到外部服务

#### 15.1.2 凭证管理
- **安全存储**：使用IDE的安全存储API保存API密钥
- **权限分离**：不同AI服务的凭证独立管理
- **自动清理**：会话结束后清理内存中的敏感数据

### 15.2 攻击防护

#### 15.2.1 输入验证
- **路径遍历防护**：确保文件访问限制在项目目录内
- **恶意代码检测**：不分析或处理可疑的代码模式
- **资源限制**：防止通过特殊构造耗尽系统资源

#### 15.2.2 输出过滤
- **提示词注入防护**：清理发送给AI的上下文内容
- **响应验证**：检查AI返回的代码是否符合安全规范
- **沙盒执行**：可选的安全执行环境测试生成代码

## 附录C：故障排除指南

### C.1 常见问题

1. **问题**：插件没有反应
   **检查**：查看输出面板中的插件日志
   **尝试**：重启插件或重新加载窗口

2. **问题**：AI生成质量没有改善
   **检查**：上下文预览面板显示的内容是否相关
   **调整**：增加核心层token分配，减少参考层

3. **问题**：分析速度慢
   **检查**：项目大小和配置的分析深度
   **调整**：降低分析深度，启用更多缓存
